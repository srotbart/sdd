# Target: Plugin skill text is self-contained — no internal spec-ID references

## Current statement

The SKILL.md files under `plugin/skills/` are the shipped product, installed
into other projects — where this repo's spec item IDs refer to nothing, or
collide with the consuming project's own domains. Yet 21 references to
`SPEC-wf-*` IDs exist across 9 skill files (close-domain, work-item-close,
spec-audit, gap-to-work-items, review-issues/improvements/engage,
target-engage, session-start), written by workers citing the governing item
of each change.

Rule: skill text states behavior self-containedly; it never cites this repo's
internal artifact IDs. Provenance belongs to commits and the spec items'
`Tests:` links, which do not ship. Generic placeholders in examples (e.g.
`SPEC-auth-001` in sample output) are fine — they are illustrative schema,
not references.

Remediation: rewrite the 21 citation sites to carry the rule inline; update
any spec tests that assert ID strings inside SKILL.md to assert the behavior
phrases instead; add a drift check (extend `check-skills-drift.js` or
lint-check) failing on `SPEC-wf-` matches inside `plugin/skills/**/SKILL.md`
so the leak cannot recur.
