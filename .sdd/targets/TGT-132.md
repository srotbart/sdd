# Target: The shipped plugin is self-contained — it never references this repo's own spec

## Current statement

Everything under `plugin/` is the shipped product, installed into other
projects — where this repo's spec item IDs refer to nothing, or collide with
the consuming project's own domains. Yet ~42 references to `SPEC-wf-*` IDs
exist across all shipped surfaces: 21 in 9 SKILL.md files, 16 in
`plugin/references/**` (schemas.md, sdd-pipeline.md, artifact guides), and 5
in `plugin/scripts/**` comments (lint-check.sh, spec-index.js) — written by
workers citing the governing item of each change (dogfood leakage).

Rule (to be minted as a spec item at engage): **the plugin never relies on or
references the SDD repo's own spec** — all shipped text and code states its
behavior self-containedly. Provenance belongs to this repo's commits and the
spec items' `Tests:` links, which do not ship. Generic placeholders in
examples (e.g. `SPEC-auth-001` in sample output) are fine — illustrative
schema, not references.

Remediation: rewrite all citation sites across `plugin/**` to carry each rule
inline; update any spec tests that assert ID strings inside plugin files to
assert behavior phrases instead; add a mechanical drift check (lint-check or a
dedicated script) failing on `SPEC-wf-` matches anywhere under `plugin/`
(excluding legitimate generic examples) so the leak cannot recur.
