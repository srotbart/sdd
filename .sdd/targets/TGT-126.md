# Target: Archived SDD artifacts leave version control; ephemeral artifacts get hash IDs

## Current statement

Terminal SDD artifacts (archived targets, closed gaps, done work-items, resolved
issues/improvements) must stop accumulating in git — currently 483 files (~1.7MB)
under `.sdd/*/archive/` that inflate PR diffs, clutter review, and grow main's
tree forever. The end-state: version control holds only the permanent truth
(specs, standards) and in-flight temporaries (open targets, gaps, work-items,
issues, improvements).

Settled decisions (full detail in `.sdd/design/archive-slimming/design.md`):

- **Archive dirs become gitignored** — the `mv`-to-archive flow is unchanged, but
  archive copies are local-only, never committed or pushed. Spec archives
  (deprecated/aliased items) stay tracked — they are permanent truth.
- **Commit-before-archive rule** — each archiving skill's closing step commits
  the artifact's terminal state *before* the `mv`, so git history remains a
  complete record; recovery when ever needed is manual `git log`/`git show`.
- **Hash IDs for ephemeral types** — new gaps, work-items, issues, improvements
  mint `{PREFIX}-{abbrev}-{7hex}` (e.g. `GAP-wf-3f9c2a1`); zero-coordination
  minting, no recycling. Targets and specs stay sequential (TGT max-seq from
  active files + history scan). Existing IDs are never renamed; all consumers
  accept both forms.
- **No ledger, no archive branch, no recovery tooling** — considered and
  rejected as over-engineering.
- **Migration** — one PR: gitignore entries, `git rm -r --cached` the 483 files,
  skill/doc updates, lint backstop (fail on tracked files under ignored archive
  paths), hub auto-link regex widened for hash IDs.
