# Target: Worker v2 — close-domain loop with cross-domain spec compliance

## Current statement

The sdd-worker must own its own spec compliance — the lead should never have to
tell it to "do a better job". Two observed failures share one root cause
(worker behavior living only in a long spawn prompt): the worker satisfies the
audited domain's spec while violating established spec items from other
domains/scopes, and the worker idles at interactive `Next:` footers instead of
driving the loop (TGT-123, superseded by this target).

Settled decisions (full detail in `.sdd/design/worker-v2-compliance/design.md`):

- **New orchestration skill `/sdd:close-domain {domain}`** internally drives
  the whole loop: Phase 0 orient (spec index + first-report handshake) →
  audit → decompose → per-work-item close with cross-domain spec context and
  self-check → Phase 4 guardian audit. Inner skills' `Next:` footers are
  advisory inside it; stop conditions are exactly nothing-to-do / all-clean /
  escalation.
- **`plugin/scripts/spec-index.js`**: deterministic, script-built, ephemeral
  (never committed) full-corpus index — one line per active item
  (`id, domain, title, scope globs`); run at Phase 0, re-run at Phase 4.
  The title IS the description; no separate summary field.
- **Per-work-item discovery**: relevant spec items selected via index +
  `scope:` globs; a read-only spec-discovery subagent only when inconclusive.
  Full text loaded before implementing; diff self-checked against every
  selected item before a work item is marked done ("tests pass" is not
  completion).
- **Guardian audit** (Phase 4): map this run's changed files to governing spec
  items across ALL domains; violations in own fresh work are fixed inline and
  re-audited (no gap artifacts); escalate on judgment calls (spec tension,
  2 fix-cycles without convergence); pre-existing violations are reported as
  candidate gaps, never inline-fixed. Completion is gated on a clean audit.
- **Slim spawn prompt**: identity + one imperative (first action = invoke
  close-domain; no other procedure) + standing rules (never touch specs or
  targets; report only at completion/nothing/blocker; surface lead-instruction
  vs spec conflicts instead of complying). Model stays per SPEC-wf-021.
- **Optional `scope:` frontmatter** on spec items: path globs
  (minimatch, repo-root-relative), opt-in for cross-cutting items only,
  recall-oriented; no backfill.
- **Out of scope**: code→spec annotations (parked as TGT-127), semantic
  search (TGT-095), multi-worker parallelism.
