# Target: Coding conventions become spec items in a conventions domain

## Current statement

**GATED — do not engage until worker-v2 (PR #21) has completed at least one
real close-domain cycle in production use.** Design is settled; only the ship
timing waits on the bake (iteration philosophy).

Retire `.sdd/standards/` and express coding conventions as ordinary spec items
in a new `conventions` domain (abbrev `conv`), riding worker-v2's discovery
machinery. Settled decisions (full detail + item-by-item migration table in
`.sdd/design/conventions-domain/design.md`):

- Every convention passes the normal spec-item bar (verifiable Invariant +
  Acceptance criteria); `scope:` path globs are mandatory in this domain.
- Fully auditable: `/sdd:spec-audit conventions` is a normal audit; gaps must
  cite concrete file:line violations.
- Mechanical rules (indent, const/var, import order, no-any) route to
  linters/tsconfig, never to spec items.
- Migration buckets: ~9 proposed SPEC-conv items (markdown-via-shared-
  component, duplication ceiling, explicit errors, input validation, file
  layout, shared components, thin handlers, single source, guarded side
  effects); mechanical → lint config; unverifiable/superseded → dropped.
- Governance: SPEC-wf-028 deprecated with a successor item (conventions are
  user-authored spec items; verifiability bar; mandatory scope); SPEC-wf-029
  amended (three layers survive — layer 1 becomes index/discovery);
  CLAUDE.md + review-issues rubric rewired; reviewer severity table moves into
  the review-issues skill.
- Conventions remain user-authored intent — negotiated via targets; the agent
  does not invent them.
