# Target: Worker-v2 refinements from the maiden-voyage bake findings

## Current statement

Four refinements observed during close-domain's first real cycle and the
parallel argus session (2026-07-03), settled in dialog with the user:

1. **Escalate on spec edit** — execution never modifies spec item files. A gap
   whose fix requires editing a spec item is an escalation to the lead, not a
   close (maiden voyage: the worker restructured SPEC-wf-017.md itself —
   faithful, but out of lane). Exception: the *permitted mechanical writes* —
   `**Tests:**` block linking (spec-test) and `scope:` backfill (item 4) —
   which never touch invariant or acceptance-criteria content.
2. **Report honesty** — every factual claim in a worker's completion/guardian
   report must be verified against the current tree at reporting time (maiden
   voyage: the report cited pre-existing dirty files that did not exist).
3. **Invoker guard** — close-domain is the sdd-worker's operating loop. Its
   description and preamble must say so and redirect a lead/main session to
   `/sdd:spawn-sdd-worker {domain}` (observed: a lead self-invoked close-domain
   because the description names the outcome, not the executor). Soft guard
   only — hooks cannot distinguish lead from worker sessions.
4. **Scope lifecycle** — `scope:` is not authored at target-engage (the spec
   precedes the code: chicken-and-egg); it crystallizes from implementation.
   Omitted or best-effort at engage; back-filled/refined at work-item-close
   from the actual diff as a permitted mechanical spec write (same class as
   `**Tests:**` blocks — globs + version hash only); the guardian audit flags
   scope-vs-diff drift instead of letting globs rot.
