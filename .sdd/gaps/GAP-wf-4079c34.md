# Gap: Archiving skills do not commit terminal state before mv, and do not forbid staging archive paths

**Locations:**
- `plugin/skills/work-item-close/SKILL.md:80-93` — steps 7-8 flip status then `mv` to `archive/` with no commit in between
- `plugin/skills/target-engage/SKILL.md:101,113,136` — target `mv` to `.sdd/targets/archive/` with no preceding commit of the accepted/archived state
- `plugin/skills/review-engage/SKILL.md:82,93,102` — issue/improvement `mv` to `archive/` with no preceding commit of the accepted/dismissed state
- `plugin/references/artifacts/*.md` — no documentation of the commit-before-archive ordering or the merge-commit-only (no squash/rebase) caveat

**Reasoning:** Every archiving flow moves the file into `archive/` without first committing the terminal state, and none forbids staging archive paths; once archives are untracked (SPEC-wf-035) the `mv` reads to git as a plain deletion, so without a prior commit git history would never retain the artifact's final content — SPEC-wf-036 requires write-terminal-state → commit → `mv`, plus the merge-strategy caveat in the operating guides.
